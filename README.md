# CineCast — совместный просмотр в Telegram

Бот поднимает **RTMP-видеочат** в группе и вещает туда YouTube / VK Video / прямые ссылки
через `yt-dlp` + `ffmpeg`. Участники просто заходят в видеочат группы и смотрят синхронно.
Задержка — секунды, а не минуты: поток идёт напрямую в инфраструктуру Telegram.

```
YouTube / VK Video ──► yt-dlp ──► ffmpeg ──► rtmps://…/<key> ──► видеочат группы
                                      ▲
                     bot.js (grammY)  │  RTMP-ключ через MTProto (teleproto)
```

Библиотеки: [grammY](https://grammy.dev) для Bot API 10.x и
[teleproto](https://docs.teleproto.dev) — поддерживаемый форк GramJS
(сам `telegram` заархивирован). Если в окружении остался старый пакет
`telegram`, бот подхватит его автоматически.

---

## Как это устроено

Bot API **не умеет** создавать видеочаты и получать RTMP-ключ — это делает только
пользовательский аккаунт по MTProto. Поэтому:

* **Бот** (`BOT_TOKEN`) — весь интерфейс: меню, очередь, настройки, статус.
* **Аккаунт-вещатель** (`MTPROTO_SESSION`) — вызывает `phone.createGroupCall(rtmp_stream=true)`
  и `phone.getGroupCallStreamRtmpUrl`, чтобы получить `url` + `key`.
* **ffmpeg** — толкает поток на этот адрес.

Аккаунт-вещатель должен быть **администратором группы** с правом «Управление видеочатами».
Группа должна быть **супергруппой** (обычные группы RTMP не поддерживают).

## Быстрый старт

```bash
git clone <repo> cinecast && cd cinecast
cp .env.example .env         # заполнить BOT_TOKEN, API_ID, API_HASH, ADMIN_IDS
docker compose build

# один раз — авторизовать аккаунт-вещатель и получить MTPROTO_SESSION
docker compose run --rm bot node bot.js login
# вставить полученную строку в .env → MTPROTO_SESSION=

docker compose up -d
docker compose logs -f
```

Без Docker:

```bash
npm install
node bot.js login     # получить MTPROTO_SESSION
node bot.js doctor    # проверить ffmpeg / yt-dlp / сессию
node bot.js
```

На хостинге `.env` не нужен — образ его не содержит, значения задаются
переменными окружения панели.

### Если панель не даёт shell

Многие веб-терминалы блокируют `docker compose run`, и выполнить
`node bot.js login` негде. Тогда вход делается прямо в боте:

1. В переменных окружения задайте `BOT_TOKEN`, `ADMIN_IDS`, `API_ID`, `API_HASH`.
   `MTPROTO_SESSION` оставьте пустым.
2. Запустите контейнер, напишите боту в личку `/login`
   (или «Админ-панель» → «Аккаунт-вещатель»).
3. **Войти по номеру** → телефон → код → при необходимости облачный пароль.
   Сессия сохранится в SQLite в `/app/data` и переживёт перезапуск.

> Код подтверждения присылайте **через дефисы**: `1-2-3-4-5`.
> Telegram аннулирует коды, отправленные в чат слитно.

Кнопка «Показать строку» выдаёт готовую `MTPROTO_SESSION` — её стоит
перенести в переменные окружения панели, а сообщение удалить.
Есть и третий путь: получить строку на своём компьютере
(`npm i && node bot.js login`) и вставить её в боте через
«Вставить строку сессии».

Сообщения с кодом, паролем и строкой сессии бот удаляет сам.

## Подключение группы

1. Добавьте бота в супергруппу и сделайте администратором.
2. Добавьте туда же аккаунт-вещатель, выдайте ему право **«Управление видеочатами»**.
3. Отправьте в группе `/setup`.
4. Пришлите ссылку на видео → «Запустить эфир».

## Команды

**В группе**

| Команда | Что делает |
|---|---|
| `/setup` | подключить группу |
| `/play [ссылка]` | запустить эфир (без ссылки — берёт первое из очереди) |
| `/add ссылка` | добавить в очередь |
| `/queue` | показать очередь |
| `/skip` | следующее видео |
| `/stop` | остановить эфир |
| `/menu` | меню трансляции |

Просто отправленная в группу ссылка тоже попадает в очередь.

**В личке** — `/start`, всё остальное через инлайн-меню.
Для админов бота: `/login` — подключение аккаунта-вещателя, `/cancel` — сброс текущего ввода.

## Режимы кодирования

| Режим | Когда применять |
|---|---|
| `auto` | по умолчанию: `-c copy`, если источник уже H.264 + AAC, иначе перекодирование |
| `copy` | минимум CPU и задержки; часть источников Telegram не примет |
| `transcode` | всегда `libx264 -tune zerolatency`, стабильнее, грузит CPU |

Параметры `DEFAULT_QUALITY`, `DEFAULT_VBITRATE`, `GOP_SECONDS` и прочее — в `.env`,
для каждой группы отдельно переопределяется в меню «Настройки».

Ориентир по нагрузке: `copy` — почти 0 % CPU; `transcode` 720p30 `veryfast` —
примерно 1–1.5 ядра на поток.

## Приватные и возрастные видео

```env
YTDLP_COOKIES=/app/cookies.txt
```

Куки экспортируются из браузера в формате Netscape; файл монтируется в контейнер
(см. закомментированную строку в `docker-compose.yml`).

## Частые ошибки

| Сообщение | Причина |
|---|---|
| `Аккаунт-вещатель не подключён` | нет сессии — `/login` в личке с ботом |
| `PHONE_CODE_INVALID` при входе | код отправлен слитно и аннулирован Telegram — присылайте `1-2-3-4-5` |
| `Аккаунт-вещатель не видит эту группу` | аккаунт не состоит в группе |
| `нет права «Управление видеочатами»` | выдайте право в настройках админов группы |
| `Telegram отклонил видеочат` | это обычная группа, а не супергруппа |
| `Источник требует авторизации` | нужны куки (`YTDLP_COOKIES`) |

`node bot.js doctor` (или кнопка «Диагностика» в админ-панели) показывает состояние
ffmpeg, yt-dlp, базы и MTProto-сессии.

## Структура

```
bot.js              весь бот: БД, UI, MTProto, ffmpeg-движок
package.json
.env.example        шаблон конфигурации
Dockerfile          без COPY .env
docker-compose.yml
data/cinecast.db    SQLite (создаётся автоматически)
```

Таблицы: `users`, `chats`, `queue`, `sessions`, `meta`.

## Правовая заметка

Трансляция чужого контента в группу может нарушать условия использования
YouTube/VK и авторские права. Используйте бота для материалов, на которые у вас
есть права, либо в приватных группах с личными записями.
